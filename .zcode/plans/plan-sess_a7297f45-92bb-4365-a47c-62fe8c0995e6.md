## Workstream B — Weather one-click care adjustments

**Storage** — Dexie **v25** in `src/db/database.ts`: `weatherAdjustments: 'id, kind, plantId, expiresAt'` (one row per affected plant). Expiry is **computed at read time** (`expiresAt > now`), no cron — same precedent as `reminderLog` pruning.

**New `src/services/weatherAdjustments.ts`** — pure core + thin Dexie CRUD:
- `activeAdjustments(rows, now)` — filters expired.
- `effectiveNextWaterDue(plant, adjustments, now)` — **heat** adjustment brings watering forward (~⅔ interval = the plan's "water 50% more often"); **frost**/**dry-air** don't touch watering (suppressing water in cold, or scheduling "group pots", would be advice the data can't support) — they mark protection active instead.

**UI** — `src/components/home/GardenDashboard.tsx` alert card (~:72-91) gains "Apply protection to N plants" (creates rows for `plantsAffectedByAlert(alert, plants)`, toast confirmation, follows the existing `QuickActionsFab` one-click pattern). Applied alerts collapse to a "🛡 Protected until {date}" chip; effects auto-expire after 7 days.

**Reminder engine** — `NotificationService.evaluate` loads active adjustments and uses `effectiveNextWaterDue` for the watering check (heat only).

## Workstream C — Assistant context + actions

**Shared pure module `src/lib/assistantContext.ts`** (server.ts already imports from `src/lib/*` — precedent: `serpApiClient.ts`, `guestQuotaStore.ts`):
- `buildGardenContext(plants, tasks, alerts, profile)` — compact serializable summary: ≤12 non-demo plants (name, species, guardianScore, status, nextWaterDue, stale days), top priority tasks, weather alerts + affected plant names, gardener skill level.
- `buildGardenPromptBlock(ctx)` — the system-prompt section ("THE KEEPER'S GARDEN: reference these actual plants by name; never invent plants; admit what you don't know").

**Server** — `POST /api/chat` (`server.ts:2040`): accept optional `garden` field, validate + size-cap (≤8 KB, following the 20 KB cap at `server.ts:2138`), append `buildGardenPromptBlock` to `systemPrompt` when present. No new route, no new env vars, `log.*` only. Privacy note: this stays within the existing Gemini boundary — `/api/guardian/predict` already sends full check-in history + weather.

**Client** — `src/services/chatService.ts` passes optional context; `src/components/FloatingAssistant.tsx` and `src/pages/Assistant.tsx` build it on open from `useLiveQuery(db.plants)` + cached `getCachedWeather` (skipped silently when no location consent) + `gardenerProfile()`.

**One-click actions** — client-computed chips under the composer, derived from the same `buildPriorityQueue` the dashboard uses (no Gemini function-calling, works offline): "💧 Water N thirsty plants" (reuses the `QuickActionsFab.tsx:99-123` water-all loop), "📝 Save last reply to notes" (pattern already in `Assistant.tsx:263-301`), "📸 Check in on {plant}" navigation chips.

## Workstream D — Honest library gamification

**Badges** — extend `ProfileBadgeCriteria` + `evaluateProfileBadges` (`src/services/profileUtils.ts`):
- `Moss Pole Climber` — best quiz streak ≥ 7 (`mastery`)
- `Quiz Master` — ≥ 90% accuracy over ≥ 25 answers (`mastery`)
- `Folio Botanist` — every folio plate marked studied (named to avoid collision with the existing Pro-tier "Guild Scholar")

`libraryEngagement.ts` exposes `quizRecord()` (correct/total — `readAccuracy` is currently private). `src/pages/Profile.tsx` feeds the new criteria at its existing `evaluateProfileBadges` call site; badges render automatically in the existing folio.

**Plant-aware recommendations** — pure helper `folioMatches(notes, species)` matching the user's real plant species (via `useLiveQuery(db.plants)`) against `PHYTO_NOTES` scientific/common names → a "From your garden" strip in `src/pages/Library.tsx` linking to matching plates. Hidden entirely when there are no matches — no filler. The deleted `DidYouKnowCard` stays deleted; the leaderboard/community-feed features are dropped per the honesty decision.
